# Moon Light — этап 2: расширение функционала и базы данных

## Запуск
1. Установите Python 3.10+.
2. Запустите `run.bat` или `python server.py`.
3. Сайт: http://127.0.0.1:8000
4. Админ-панель: http://127.0.0.1:8000/admin

Демо-администратор: `admin@moonlight.local` / `MoonLight2026!`

SQLite-файл `moon_light.db` создаётся автоматически. При обновлении базы существующие данные сохраняются: новые поля добавляются миграциями.

## Что добавлено на этапе 2
1. Привязка бронирования к аккаунту, если гость авторизован.
2. Личный список броней: `GET /api/my-bookings`.
3. Получение профиля: `GET /api/profile`.
4. Изменение имени и телефона профиля: `PATCH /api/profile`.
5. Смена пароля с проверкой текущего: `POST /api/change-password`.
6. Статус оплаты для бронирований: `unpaid`, `paid`, `refunded`.
7. Время последнего изменения бронирования.
8. Причина отмены как отдельное поле БД (зарезервировано для следующего расширения).
9. CSV-экспорт броней для Excel: `GET /api/export/bookings.csv` (только администратор).
10. Месячный отчёт: `GET /api/reports/monthly` (только администратор).
11. Индексы SQLite для поиска по датам, пользователю и модерации отзывов.
12. Миграции схемы для уже существующих баз без удаления записей.
13. Обновлён health-check: этап 2.
14. В админском PATCH можно менять статус оплаты бронирования.

## API этапа 2
- `GET /api/my-bookings` — брони текущего аккаунта.
- `GET /api/profile` и `PATCH /api/profile` — просмотр и изменение профиля.
- `POST /api/change-password` — смена пароля (`current_password`, `new_password`).
- `GET /api/export/bookings.csv` — CSV-экспорт всех броней (администратор).
- `GET /api/reports/monthly` — сводка по месяцам (администратор).
- Статусы оплаты в `PATCH /api/bookings/ID`: `payment_status=unpaid|paid|refunded`.

Для авторизации передавайте заголовок `Authorization: Bearer <token>`. Токен возвращается при `POST /api/login`.

## Проверки
При подготовке выполнены компиляция Python и тесты инициализации SQLite/миграций. HTTP-проверка через браузер на вашем компьютере остаётся обязательной после распаковки.

## Ограничения учебной версии
Сессии хранятся в памяти сервера; пароли пока хешируются SHA-256 без соли. Нет HTTPS, CSRF-защиты, rate limiting, восстановления пароля и платёжного шлюза. Не публикуйте демо-пароль в интернете; для реального запуска нужны усиленное хеширование (например, Argon2/bcrypt), безопасные cookie и полноценные тесты.
